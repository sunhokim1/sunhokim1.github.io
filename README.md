# GitHub Pages 배포와 새 글 작성

## 처음 올리기
1. ZIP을 압축 해제하세요. ZIP 파일 자체가 아니라 압축을 푼 **안의 파일과 폴더**를 올립니다.
2. GitHub에서 로그인하고 `sunhokim1.github.io` 저장소를 엽니다. 없다면 같은 이름으로 새 저장소를 만듭니다. GitHub Free에서는 공개 저장소를 선택하세요.
3. 저장소의 **Add file → Upload files**에서 압축을 푼 내용 전체를 올립니다. `_config.yml`, `index.html`, `_posts`, `_layouts`, `assets`가 저장소 첫 화면에 직접 보여야 합니다. 폴더가 중첩되지 않도록 확인하세요. 기존 같은 이름 파일이 있으면 덮어쓰기 전에 백업하세요.
4. **Commit changes**를 누릅니다. 저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**, `main` (기본 브랜치가 다르면 해당 브랜치), `/(root)`를 선택하고 **Save**를 누릅니다.
5. 배포가 완료되면 https://sunhokim1.github.io/ 에 접속합니다. 반영에 최대 10분 정도 걸릴 수 있습니다. 안 되면 저장소의 Actions에서 빌드 오류를 확인하세요.

GitHub Pages는 브랜치에서 배포할 때 기본적으로 Jekyll을 사용합니다. `.nojekyll` 파일이 저장소에 이미 있다면 Jekyll이 실행되지 않으므로 제거해야 합니다. 기존 사이트가 있다면 먼저 백업하고 영향을 확인하세요.

## 새 글 쓰기
1. 저장소에서 **Add file → Create new file**을 선택합니다.
2. 파일 이름에 `_posts/2026-10-28-new-project.md`처럼 입력합니다. 날짜는 작성일, 영문 이름은 글마다 다르게 입력하세요. 미래 날짜의 글은 기본 설정에서 게시되지 않습니다.
3. 아래 내용을 붙여 넣고 제목, 분야, 요약, 본문을 수정합니다. 분야는 `MCU-AVR`, `FPGA-RTL`, `Embedded-Linux`, `AI-시스템` 중 선택하거나 새 이름을 써도 됩니다.

```markdown
---
layout: post
title: "글 제목"
categories: [MCU-AVR]
summary: "글 목록에 보일 한 줄 설명"
---

## 프로젝트 개요
프로젝트를 설명합니다.

## 사용 기술
- MCU 또는 개발 환경
- 사용한 기술

## 구현과 문제 해결
구현 내용과 해결 과정을 작성합니다.
```

4. **Commit changes**를 눌러 기본 브랜치에 저장하면 Pages가 다시 빌드됩니다. 글은 첫 화면과 분야 목록에 자동으로 나타납니다.
5. 이미지를 사용하려면 `assets/images`에 올리고 본문에 `![설명](/assets/images/파일명.png)`처럼 적으세요. 파일명은 영문과 숫자를 권장합니다. 공개하면 누구나 파일을 볼 수 있으니 개인정보와 공개 권한을 확인하세요.

## 현재 글에 관한 안내
6개 프로젝트 글은 전달받은 발표자료와 GitHub README를 바탕으로 작성했습니다. 글 파일의 2020년 날짜는 정렬용이며 실제 수행 날짜가 아닙니다. 글에서 프로젝트 날짜는 표시하지 않습니다. 자료 속 프로젝트는 팀 작업이 포함되어 있으므로 공개 전에 개인 역할과 공유 권한을 확인해 주세요.
